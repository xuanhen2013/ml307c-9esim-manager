# ML307C 适配与 Windows 启动

本分支在原项目的 Python 服务和 React / shadcn 界面上增加 ML307 AT/APDU 后端。无需通过 lpac 查询卡列表或执行切换；原 ModemManager 后端仍保留。

## Windows 启动

先安装设备所需的 USB 串口驱动，在设备管理器确认 AT 串口。需要 Python 3.12 和 Node.js/npm。关闭其他占用同一串口的程序，再运行：

```powershell
.\start-ml307.ps1 -SerialPort COM4 -ListenPort 8080
```

将 `COM4` 改为实际 AT 串口。也可以双击 `start-ml307.cmd` 使用默认参数。打开 <http://127.0.0.1:8080/>。

脚本自动创建 `.localdata/venv`、安装 `requirements-ml307.txt` 并在首次启动时构建前端。前端改动后在 `frontend` 目录重新运行 `npm.cmd run build`；后端改动后重启服务。Windows 休眠或关闭进程会停止接收。

常驻 NAS 部署见 [DEPLOY-NAS.md](DEPLOY-NAS.md)。不要同时在两台主机上运行使用同一飞书 App ID 的长连接客户端。

## 收件与切卡

后台每 5 秒读取短信；网页默认每 10 秒刷新，可选择间隔或暂停。关闭网页不影响后台接收。首次已有短信标记为历史导入，不猜测收件卡、不转发历史导入项。新短信使用本机观察到的接收时间，保留短信中心原始时间。

切卡与接收共用设备锁，先保存旧卡收件，再启用目标配置并等待网络注册。切卡不会删除短信。读取设备短信可能将未读改为已读，程序不自动清空模组存储。

## 驻网与信号

当前卡品牌与驻网运营商分别显示。驻网以 `AT+COPS?` 的数字 PLMN 为准：临时使用 `AT+COPS=3,2` 读取后恢复显示格式，不改变选网方式。未知 PLMN 显示数字，不从卡品牌推测网络名称。

信号来自 `AT+CSQ` / `AT+CESQ`。LTE 显示 RSRP、RSRQ，另保留 RSSI、CSQ；CESQ 是分档测量，显示区间而非伪造精确值。暂不显示未获取的 SINR、频段。换算依据 [ETSI TS 127 007](https://www.etsi.org/deliver/etsi_ts/127000_127099/127007/15.02.00_60/ts_127007v150200p.pdf)。

## 保号任务

可设置起算日期、首次等待天数、首次发送时间（北京时间）、后续间隔、收件号码和短信内容。例如首次 70 天，此后每次短信提交成功后 85 天。所有规则存入 `keepalive.sqlite3`，不会随容器重建丢失。

执行过程：切到指定卡 → 等待注册 → 提交单条 UCS2 短信（最多 70 字，不支持 emoji）→ 恢复原卡 → 飞书通知。收件号码使用 `+国家区号` 格式，需要目标运营商允许漫游发送且余额充足。

同时取得 `+CMGS` 和 `OK` 后才顺延下一次日期。这代表模组确认提交，不代表对端收到或运营商已确认计费。短信失败不顺延、不自动重发；排查后关闭、保存，再重新开启任务可重试。结果不明或发送途中重启时保持暂停，需要人工核对发送记录。即使恢复原卡失败，已确认提交的短信也不会重复发送。

NAS 离线错过执行时间，恢复后补执行一次；后续日期从实际提交成功时刻计算。开启已到期的任务可能很快执行，不应使用真实模组做过期时间测试。

## 适配范围

Linux usbfs 当前只接受 VID/PID `2ecc:3012`、接口 2 未绑定驱动、端点布局匹配的设备，不会强制卸载驱动。已有 USB 串口时可以设置 `ML307_PORT` 为对应串口路径，但需要在 Compose 中自行映射该设备。

目前不开放任意手动发送、重启基带或网络配置。真实出站计费短信尚未实机验收；365 天未收验证码提醒尚未实现。已验证功能和整体范围见 [README](README.md)。
